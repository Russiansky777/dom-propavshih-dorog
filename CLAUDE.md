# Дом пропавших дорог — контракт для Claude Code

2D point-and-click на Godot 4.7.x (GDScript). Браузер (itch.io) + Windows/macOS/Linux из одного проекта.
Автор проекта — Директор: принимает творческие решения, утверждает образцы, проходит сборки.
Агенты владеют технической частью и никогда не просят Директора чинить код.

## Прочитать первым
1. `Docs/CURRENT_STATE.md` — единственный источник контекста при входе в новый чат: что сделано, чем доказано, следующее действие.
2. `Docs/DECISIONS.md` — принятые решения и их причины; не переоткрывать без новых фактов.
3. `data/story/` — сценарий как данные (истина для реализации). Литературный текст — `story_source/`.
4. `Docs/MILESTONES.md`, `Docs/TEST_PLAN.md` — что считается готовым и как это проверяется.

## Неизменный канон (не менять без решения Директора)
- Агата 25 (24 при разрыве), Нина 67, Илья 32, Ульяна 8, Митя 37, Пелагея 40, Павел 48, Тамара 53. Евдокия умерла в 72 за два местных года до событий.
- Снаружи прошёл год, внутри двадцать лет. Прожитое не стирается: никакого омоложения, воскрешения, стирания детей.
- Закон мира: «Вещи помнят место, которому служили. Дорогу держат с двух концов».
- Зеркало показывает нынешний вид со своего прежнего места. Не портал, не телефон, не машина времени.
- Эхо в кабинете мельницы — повтор незавершённого действия, не человек и не душа.
- Один технический финал: два постоянных входа, общее время. Личные выборы меняют детали, не судьбу деревни.
- Тихон — печной зверёк-смотритель: не подсказчик, не питомец с уходом, не вор обязательных предметов.
- Имя «Дарья» не используется.

## Границы владения
- `game/`, `data/`, `tools/`, `Docs/` — Claude Code. Codex здесь не правит файлы.
- `pipeline/` и `assets/` (кроме `assets/manifest.json`) — Codex. Claude Code здесь не правит файлы.
- `assets/manifest.json` — контракт: Claude Code пишет, что нужно; Codex отмечает готовое; Claude Code импортирует.
- `story_source/` — только чтение; текст меняет ChatGPT с Директором, новая версия кладётся файлом.

## Структура
```
game/           проект Godot (project.godot, scenes/, scripts/, data → symlink или копия data/story)
data/story/     locations.json items.json flags.json scenes/*.json quests.json
tools/          validate_story.py, run_tests.sh, export_web.sh, screenshots.mjs
pipeline/       Meshy/Blender/TTS-конвейер (Codex)
assets/         готовые ассеты по манифесту
Docs/           CURRENT_STATE, DECISIONS, MILESTONES, TEST_PLAN, STYLE_BIBLE, ASSET_PROVENANCE
story_source/   сценарий v3 (md), концепты
```

## Команды проверки
- `python3 tools/validate_story.py` — должен завершаться кодом 0 перед любым коммитом, меняющим `data/story/`.
- `tools/run_tests.sh` — headless-тесты Godot (GdUnit4 или скриптовые), код 0.
- `tools/export_web.sh` — веб-сборка в `build/web/`; `node tools/screenshots.mjs` — скриншоты комнат в `build/shots/`.
- Реальные клики и полное прохождение подтверждают результат, не скриншот.

## Правила работы
- Контент — данные, не код: комнаты, хотспоты, предметы, реплики, условия живут в `data/story/` и ресурсах Godot, не в if-ветках скриптов.
- Флаги со смысловыми именами (`door_school_installed`), никогда координаты рисунка в сюжетном состоянии.
- Обязательный предмет не исчезает и не выдаётся дважды. Любая цель объяснена до требования её выполнить.
- Сохранение/загрузка не повторяет одноразовые события и не блокирует продвижение.
- Каждый найденный дефект превращается в автопроверку.
- Секреты только в `.env` (в `.gitignore`) и в переменных окружения. Ключ перевыпускается, если перестал работать или утёк за пределы команды (решение Директора 17.10).
- Право отказа: задание, снимающее защитный барьер (ключи, деньги, публикация, удаление чужой работы), останавливает агента и требует вопроса Директору.

## Передача на проверку Директору
Директор не читает код и не угадывает, что смотреть. Любая передача на проверку — файл `Docs/ACCEPTANCE_<веха>.md`: где проверять (ссылка, файл, команда), список критичного с ожидаемым поведением по шагам, список важного, что оценивать не нужно, как ответить. Ссылка на файл и краткий список — в сообщении. Без чеклиста сборка Директору не отправляется.

## В конце каждой сессии
Обновить `Docs/CURRENT_STATE.md`: что сделано, чем доказано (логи, скриншоты, отчёты в `build/`), что не доделано, следующее действие. Закоммитить и, если есть доступ, запушить. Оставить чистое дерево.
