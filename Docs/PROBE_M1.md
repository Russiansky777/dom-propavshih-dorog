# M1 — E0–E1 на заглушках, управляемые данными: отчёт

Дата: 2026-10-17. Та же среда, что в M0 (Godot 4.7.2.stable headless, Linux-контейнер без GPU, Chromium 141 + SwiftShader, Python 3.13, Node 22). Всё ниже получено запуском команд из §6; что не проверялось — в §8.

## 1. Итог

- Эпизоды E0–E1 (M01–M08, V01–V03, Q04) проходятся от Z1 до возвращения в H3 **двумя независимыми способами**: headless-ботом через игровой API (тест, 7 с) и реальными кликами по холсту веб-сборки (Playwright, 5 мин под SwiftShader, 21 кадр). Финальные флаги `door_school_installed`, `wrote_on_board`, `knows_trip_14` — true в обоих прогонах.
- Комнаты, хотспоты, выходы, условия, подсказки, реплики — данные (`data/story/`), не код: в GDScript нет ни одного `if scene_id == …`. Комната собирается на лету из `data/story/rooms/<LOC>.json`; `.tscn` на комнату не нужен.
- `tools/run_tests.sh`: 2 валидатора данных + **13/13 PASS** headless-тестов (10 из M0 + 3 новых), код 0. Экспорты: веб 39 МБ, Linux 71 МБ, Windows 105 МБ. Консоль браузера: 0 ошибок, 14 предупреждений WebGL (см. §7).

## 2. Что построено

### Данные (`data/story/` — только `rooms/` и `text/`, остальное не трогал)

| Файл | Содержание |
| --- | --- |
| `rooms/_index.json` | `in_scope` (10 комнат вехи), геометрия по умолчанию (полигон пола, глубина, стороны выходов), описание схемы хотспота и порядка обработки клика |
| `rooms/Z1 Z2 Z3 R1 H1 H2 H3 H4 O1 O2.json` | фон (цвета/горизонт), спавны, пропсы (в т.ч. окклюдеры), **40 хотспотов**, выходы (цель и `requires` берутся из `locations.json`, в JSON только размещение/подписи/реакция «закрыто»), условия запуска/завершения сцен (`scenes`), локальные флаги с описанием |
| `text/ru_E0_E1.json` | **220 строк, все `draft: true`**: подписи, осмотры, реакции закрытых выходов, тексты UI. Обязательные реплики сцен не дублируются — берутся из `scenes/*.json` |

Схема хотспота (из `_index.json`): `rect`, `stand`, `kind` (object/npc/pickup), `visible_if`/`hidden_if`, `states` (подпись и цвет по флагам), `look`, `use` (requires/sets/gives/once_flag/text/scene), `item_use` (предмет → действие), `talk` (сцена-разговор), `choice` (варианты → флаги), `puzzle` (см. H3). Порядок обработки одного клика: выбран предмет → `item_use`; иначе `talk` → `puzzle` → `choice` → `use` (если доступно) → `look`. Один клик — осмотр или действие, без глаголов.

Запуск сцен — только данными: `talk:<хотспот>` (M01 Тамара, M02 Пелагея), `puzzle:<хотспот>` (M05), `complete_when` (список условий `all`/`any`/`any_n`: M03 — три действия в H1, M04 — дверь + мастерская + петли, M06 — 2 из 3 осмотров, M07 — накладная, M08 — петля + надпись, V01/V03/Q04 — выборы), `enter` (V02). Сцена, объявленная хоть в одной своей комнате, нигде не стартует «сама по себе» (поймано тестом: M02 запускалась при входе на Z2).

### Код (`game/`, ~4,6 тыс. строк GDScript/JS/Python вместе с тестами)

- `scripts/core/story_data.gd` — автозагрузка `StoryData`: читает все JSON из `res://data/story` (копия, см. §6), резолвит ключи `@секция.ключ`, `@char.<id>` → имя из `characters.json`, подсказки сцены в 3 уровня.
- `scripts/core/story_runner.gd` — автозагрузка `StoryRunner`: очередь «битов» (реплика / нарратив / список вариантов), `start_scene` → реплики по порядку → `grants`/`consumes`/`done_<id>` → цель журнала из `result` → автосейв; проверка триггеров комнаты после входа и после каждого флага; обработка клика по хотспоту и выходу; петля закрытого выхода (O2); логика загадки `match_marks`; подсказки по уровням (счётчик в сейве); факты журнала = описания установленных флагов из `flags.json`.
- `scripts/rooms/room_builder.gd`, `story_hotspot.gd`, `story_exit.gd` — сборка `Room` из JSON: фон (PNG из `tools/make_placeholders.py` или плоские полигоны), `Walkable`, пропсы, спавны, хотспоты (Area2D + прямоугольник + подпись, состояния по флагам), выходы (требования из рёбер `locations.json`; закрытый выход реагирует текстом, цель вне `in_scope` — текстом `ui.not_built`).
- `scripts/core/game_state.gd` — формат сейва **v2** (цель журнала, счётчики; v1 из M0 читается), `save_info` для меню; слоты `auto`, `quick`, `1..3`, зарезервирован `pre_finale`.
- `scripts/core/room_manager.gd` — комната из данных, иначе `.tscn` (`scenes/rooms/`, `scenes/probe/`); `autosave()` после каждого бита; старт из `locations.json: start`.
- `scripts/ui/game_ui.gd` — верхняя панель (комната, инвентарь с кнопками-заглушками, Журнал / Подсказка / Меню), диалог с кликом «дальше» и списком вариантов, нарратив осмотра в том же окне, журнал (цель + факты), меню слотов 1–3 + новая игра, строка подсказки, затемнение для петли. Только мышь; F5/F9 сохранены (слот `quick`).
- `scripts/ui/closeup_puzzle.gd` — крупный план загадки двери: полотно, рама с тремя гнёздами (два правильных), брус с четырьмя позициями зарубки, рисунок-эталон, лоток с двумя петлями, кнопка «Закрыть дверь». Ошибка — за открытым полотном домашняя стена и текст; после второй ошибки — `hints[0]` сцены M05 («На брусе есть зарубка»). Успех — за дверью **статичный холодный слой с падающим снегом (CPUParticles2D) и подписью «Зимний класс»**, через 2 с закрытие и реплика M05. Решение: SubViewport с O1 не делал — проще, работает в вебе, вид класса игрок получает через саму дверь секундой позже.
- `scripts/main.gd` — на вебе публикует `window.probeState` (комната, флаги, инвентарь, бит диалога, центры хотспотов/выходов/кнопок/вариантов/предметов/деталей загадки) — чтобы Playwright кликал по реальным координатам, не зашитым в скрипт.
- Проба M0 (`RoomHouse`/`RoomOffice`) перенесена в `scenes/probe/` и остаётся регрессионной фикстурой: её 10 тестов проходят без изменений.

## 6. Команды

```
python3 tools/make_placeholders.py        # фоны комнат из rooms/*.json (+ заглушки M0)
tools/run_tests.sh                        # validate_story + validate_rooms + sync + 13 тестов
tools/export_web.sh && tools/export_linux.sh && tools/export_windows.sh
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node tools/screenshots.mjs   # build/shots/m1/
```

`tools/sync_story_data.sh` копирует `data/story/*.json` в `game/data/story/` (Godot читает `res://data/story`); скрипты тестов/экспорта вызывают его сами. Копия, а не симлинк: git на Windows выписал бы симлинк текстовым файлом, и проект в редакторе у Директора остался бы без данных. Копия коммитится вместе с кодом; при расхождении тест её пересинхронизирует. `*.json` включены в экспорт через `include_filter`.

## 7. Что сломалось по дороге и как закрыто

1. **Сцена с несколькими локациями стартовала сама.** M02 (`locations: [Z2, R1]`) запускалась при входе на Z2, хотя триггер объявлен только в R1. Правило теперь: сцена, объявленная хоть в одной своей комнате, нигде не автозапускается. Поймано ботом.
2. **Хотспот под выходом.** В O1 «мешок» перекрывался задней дверью; выход побеждает при клике (приоритет 1 > 0) — бот ушёл в H3 вместо осмотра. Добавлена проверка перекрытий в `validate_rooms.py`; она же нашла ещё четыре таких места (H1 чашки/полка, R1 Пелагея, Z2 ориентиры) — все раздвинуты.
3. **`-s`-скрипт и классы.** Тест не может называть `RoomBuilder` по имени класса: его цепочка зависимостей компилируется до регистрации автозагрузок (та же причина, что в M0). В тесте — `load("res://scripts/rooms/room_builder.gd").build(...)`.
4. **Playwright: позиции UI.** Контейнеры раскладывают детей кадром позже; `probeState` публикуется через два кадра и, кроме того, по таймеру 0,4 с (переключение журнала/меню не имеет сигнала). До этого клик по «предмету» попадал в чужую кнопку, а закрытый журнал глотал клики.
5. **Затемнение петли глотало клик** по появившемуся тексту: теперь после телепорта затемнение пропускает мышь.
6. **Шрифт по умолчанию без «▸/▲»** — заменены на текст и «X».
7. **Предупреждения WebGL**: 256 за прогон из-за того, что `refresh()` хотспотов переназначал тот же цвет `Polygon2D` при каждом флаге (переназначение = перезаливка буферов). Теперь цвет/подпись меняются только при реальном отличии: 14 за прогон, остальные — перерисовка панелей `StyleBoxFlat` (движок, безвредно).
8. Подсказки HUD шли мимо `GameState.show_hint` → проба их не видела; исправлено (повтор дефекта M0 — стоит держать правило «любой текст игроку — через GameState»).

## 8. Ограничения и что не проверено

- Графика — цветные прямоугольники с подписями; фигура Агаты из M0; Эхо/зеркало M0 в E0–E1 не используются (зеркало ЗГ в H3 — осмотр, не SubViewport).
- Windows-сборка только экспортирована. Реальный GPU/браузер, Firefox/Safari — не проверялись.
- Подсказки: у сцен с одним `hint` (M04, M08) уровни 2–3 — общие фразы UI; у сцен без подсказок — все три общие. Сцена подсказки = первая незавершённая основная сцена с выполненными `requires`.
- Иконки предметов — аббревиатуры на кнопках, не PNG.
- Полигон пола — выпуклый четырёхугольник, пропсы не вырезаны (Агата проходит «сквозь» стол).
- Цель журнала после M08 — текст `result` M08 (данные), без собственной формулировки «что дальше».
