# ИИ-плейтест — ворота перед передачей Директору

Claude играет в опубликованную веб-сборку (https://russiansky777.github.io/dom-propavshih-dorog/) настоящими щелчками мыши в браузере на раннере GitHub Actions: кадр → модель выбирает одно действие → щелчок → игра успокаивается → следующий кадр. Код — `tools/ai_playtest/`, workflow — `.github/workflows/ai_playtest.yml`.

## Как запустить

Положить или изменить файл `pipeline/requests/playtest_<блок>.json` и запушить в `main` (для повтора достаточно поменять поле `run`). Вручную: Actions → ai-playtest → Run workflow → путь к запросу.

Workflow сам дождётся, пока закончится текущая сборка сайта, проверит её номер (`version.txt` попадает в отчёт) и закоммитит результат с `[skip ci]` в `Docs/playtest/<дата>_<режим>_r<номер запуска>/`.

Запускать, когда есть что проверить: передача блока Директору, проверка исправления, новая сборка нового блока. Не ради прогона.

## Формат запроса

```json
{
  "mode": "gate",
  "doc": "Docs/ACCEPTANCE_M1.md",
  "items": "140-154",
  "context_items": [95, 97, 100, 101],
  "max_steps": 300,
  "fresh_max_steps": 150,
  "note": "Что важно знать тестировщику (одна-две фразы)",
  "run": 1
}
```

| Поле | Что значит | По умолчанию |
| --- | --- | --- |
| `mode` | `acceptance` — проходит пункты чеклиста по порядку и даёт по каждому вердикт; `fresh` — новичок без спойлеров, видит только игру; `gate` — сначала `acceptance`, потом `fresh` (два отчёта) | `fresh` |
| `doc` | файл чеклиста `Docs/ACCEPTANCE_<веха>.md` | файл, где есть первый пункт |
| `items` | номера пунктов: `"140-154"`, `[140, 141]` или `"1-17,140"`. Порядок = порядок проверки: критичные — первыми | — |
| `context_items` | пункты-справка (как что делается), по ним вердиктов нет | — |
| `max_steps` | потолок шагов (действий) прогона | 300 приёмка / 150 свежий |
| `fresh_max_steps`, `fresh_note` | то же для второй половины `gate` | 150 / — |
| `max_usd` | предохранитель от зацикливания, не бюджет: прогон останавливается, если стоимость его дойдёт | 10 (больше нельзя) |
| `max_minutes` | потолок времени прогона | 120 приёмка / 90 свежий |
| `url` | другой адрес сборки | сайт GitHub Pages |
| `note` | замечание тестировщику (например, где лежит нужный предмет, если пункт этого не говорит) | — |
| `model`, `model_stuck`, `report_model` | модели шагов, шага при застревании, итогового отчёта | `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-sonnet-5-5` |
| `image_width` | ширина кадра для модели (JPEG, 16:9) | 1280 |
| `max_frames` | сколько кадров-доказательств сохранить | 24 |
| `run` | счётчик для повторного запуска | — |

Свежий прогон всегда начинается с новой игры в чистом браузере.

## Что в результате

- `report.md` — по-русски: шапка (сборка, шаги, причина остановки, стоимость прогона), отчёт сильной модели (она сверяет вердикты шаговой модели с дословными репликами и кадрами), сырые вердикты и заметки.
- `f####.jpg` — только кадры-доказательства (то, что видела модель, 1280×720).
- `usage.json` — токены и стоимость каждого вызова API по фактическому `usage`.
- `log.json` — журнал шагов, дословные реплики, куда игра реально дошла (комнаты, флаги) — для разбора самого плейтестера.

Подтверждённые дефекты из отчётов переносятся в `Docs/playtest/defects_<дата>.md` (комната, действие, ожидалось / получилось, как воспроизвести).

## Как это устроено

- Модель видит только кадр и тексты, которые на нём есть: реплики и варианты ответа, подпись под курсором, строку подсказки (программа читает их из `window.probeState` дословно, чтобы мелкий шрифт не путал вердикт). Координат объектов модель не получает — ищет сама, как человек: наводит курсор, жмёт Пробел (подписи всех мест), щёлкает.
- Реплики подряд пролистываются настоящими щелчками по окну текста; модель получает их текст и кадры первой и последней реплики, затемнения — отдельным кадром. Выбор вариантов делает модель.
- После действия программа ждёт, пока героиня дойдёт и игра успокоится, и только потом снимает кадр.
- Звук модель не слышит: части пунктов про звук помечаются «не проверяемо».
- Ключ — секрет `CLAUDE_API`, рабочее пространство — секрет `CLAUDE_WORKSPACE` (заголовок `anthropic-workspace-id` уходит, только если секрет задан). Лог Actions публичный: в нём только номера шагов, действия, комнаты и стоимость — ни ключа, ни ID, ни ответов модели.
- Цены моделей — таблица в `tools/ai_playtest/claude.mjs` по официальной странице цен; модель без цены в таблице не запускается.

## Локально

`node tools/ai_playtest/playtest.mjs --request <файл> --web-dir build/web --dry-run` — прогон без API по заранее заданным действиям (проверка браузерной части: загрузка, кадры, пролистывание, выбор, затемнения). С ключом — `ANTHROPIC_API_KEY=… [ANTHROPIC_WORKSPACE_ID=…] node tools/ai_playtest/playtest.mjs --request <файл>`.
