## Причина падения экспорта Windows (сборка 40244676826)
Падал не Godot, а сама строка скрипта: `godot … | tee … | grep -Ei 'error|warn|done|export' | head -20` при `set -o pipefail`.
В выводе Godot есть имена файлов озвучки с `done` (`H1.v01.done.ogg`, `look_done.ogg`, `open_done.ogg` …). grep быстро набирает
20 строк, `head` выходит, труба закрывается, и шаг завершается кодом **141 (SIGPIPE)**. Воспроизведено здесь прежним скриптом
и прежним пресетом: `OLD_EXIT 141`. Exe при этом успел записаться, **2,81 ГБ** — больше предела ассета релиза GitHub (2 ГиБ),
так что даже без SIGPIPE публикация бы упала. 52 минуты в сборке — это импорт без кэша (здесь 37 мин) плюс экспорт.

## Что сделано
1. **Быстрый exe (п. 0)** — пресет «Windows Lite» (`game/export_presets.cfg`): фича `web_atlas`, те же фильтры, что у веба,
   PCK вшит, путь `build/windows/DomPropavshihDorog.exe` — тот самый, который workflow уже выкладывает. **Для промежуточной
   публикации правка workflow не нужна**: достаточно запустить build_and_publish на текущем main.
2. **Полное качество (п. 2)** — пресет «Windows»: `embed_pck=false`, exe и pck → `build/windows/full/`, оттуда zip.
   Из трёх вариантов выбран «отдельный .pck». Он единственный не меняет картинку: BPTC 2,25× как есть, и видеопамять как сейчас.
   - Lossless/WebP для листов жителей отклонён: на диске меньше, но в видеопамяти RGBA 4 байта на пиксель вместо 1 у BPTC.
     Лист Нины v2 — 205 Мпикс: ≈ 1,1 ГБ видеопамяти на одну Нину против ≈ 0,27 ГБ сейчас. Сцена с 3–4 жителями не влезет
     в видеокарту.
   - Копии 1,5× — потеря чёткости на экранах больше 1080p, а размер в виде одного exe всё равно ≈ 2 ГБ.
   - Zip хорошо сжимает BPTC: ~46 % блоков атласов прозрачные. Поэтому 2,8 ГБ превращаются в 1,58 ГБ.
3. `tools/export_windows.sh`: убран `| head`; Lite, потом полная; zip с проверкой ≤ 1900 МБ; падение полной сборки не мешает Lite
   (`::warning`, код 0; строгий режим — `WIN_FULL_REQUIRED=1`, только Lite — `WIN_FULL=0`). Перед импортом вызывается `make_web_sheets.py`.
4. Сайт: первый прогон дал **969 МБ > 950**. Страница дублей `listen/` возила каждый дубль дважды (ogg + mp3, 80 МБ).
   Теперь только mp3, если он есть (играет во всех браузерах; Safari и раньше брал mp3), ogg — запасной.
   `listen/` 51 МБ, сайт **939 МБ**. Сама игра на сайте не менялась.
5. Автопроверка (`tools/test_web_sheets.py`, входит в run_tests): полная Windows — PCK не вшит; Lite — `web_atlas`, вшит,
   без полных листов, путь exe как у workflow. Заодно исправлен разбор пресетов: раньше блок `[preset.N.options]` не читался.
6. Сборки проверены изнутри (Linux-Godot `--main-pack`): в Lite `web_atlas=true`, веб-листы есть, полных нет; в полном pck —
   наоборот; Lite 900 кадров headless — без ошибок загрузки (при выходе только обычные сообщения об утечках).
7. Кадры `Docs/evidence/i_t7/pc_vs_lite_{nina_v2,pelageya_v2,agata}.jpg`. Текстуры взяты из самих сборок (BPTC раскодирован
   Godot, `tools/decode_pack_textures.gd`, `tools/i_t7_frames.py`): полная ПК / Lite = сайт / житель ПК от 24.10 (v1).

## Время
- Импорт без кэша: **2213 с (37 мин)**, 4 ядра (Godot загружает ~2 из 4). Почти всё время — BPTC атласов жителей v2 и Агаты.
- С кэшем импорта: импорт 3 с, экспорт Lite 4 с, полной — 16 с, zip — 62 с; веб — 12 с.
- **Как ускорить** (импорт > 20 мин): кэш `game/.godot` в workflow уже есть, но actions/cache сохраняет его только при успешной
  работе job. Все сборки 25–26.10 падали, поэтому кэш, видимо, ни разу не сохранился. Теперь шаги экспорта `continue-on-error`,
  и после первой успешной сборки кэш появится; следующие сборки — минуты. Кэш ≈ 3,1 ГБ (предел репозитория 10 ГБ),
  а ключ по `github.sha` создаёт новую запись при каждой сборке. Лучше ключ по хешу ассетов:
  `key: godot-import-${{ env.GODOT_VERSION }}-${{ hashFiles('game/assets/**/*.import', 'game/assets/characters/**/sprites.json') }}`.

## Правка workflow для координатора (`.github/workflows/build_and_publish.yml`, шаг «Publish Windows exe…»)
Для промежуточной публикации Lite ничего менять не нужно. Чтобы выкладывать и полную версию, после последней строки шага
```
          step gh release upload latest build/windows/DomPropavshihDorog.exe --clobber
```
добавить
```
          if [ -f build/windows/DomPropavshihDorog_win.zip ]; then
            step gh release upload latest build/windows/DomPropavshihDorog_win.zip --clobber
          fi
```
и в `notes` дописать: «DomPropavshihDorog.exe — один файл, картинка как на сайте; DomPropavshihDorog_win.zip — полное
качество, распаковать целиком (exe и pck рядом)». Шаг «Export Windows» уже идёт после «Export web», поэтому веб-копии листов
для Lite есть. Скрипт и сам вызывает `make_web_sheets.py`, а Pillow ставит шаг «Python + Pillow».
