# ИИ-проверки в Actions

Небольшой набор проверок на Claude API. Каждая запускается только когда меняются её входы, пишет короткий отчёт в `Docs/ai_checks/<проверка>_<дата>.md` (коммит с `[skip ci]`) и **никогда не правит game/ и data/** — находки разводит координатор. Ключ — секрет `CLAUDE_API`, рабочее пространство — `CLAUDE_WORKSPACE`; в публичный лог Actions не печатаются ни ключ, ни ID, ни ответы модели. Код — `tools/ai_checks/`, API и цены — `tools/ai_playtest/claude.mjs`. Плейтест (ворота перед передачей Директору) — `Docs/playtest/README.md`.

Ручной запуск любой проверки: поменять поле `run` в `Docs/ai_checks/requests/<проверка>.json` и запушить (или Actions → нужный workflow → Run workflow).

| Проверка | Когда запускается | Что смотрит | Отчёт |
| --- | --- | --- | --- |
| Спрайты (`ai_sprite_qa.yml`) | после каждого прогона конвейера персонажей (`pipeline-character`, через `workflow_run`: его коммиты идут с `[skip ci]`); запрос `requests/sprite_qa.json` (`"chars": "all"` или список) | глазами модели — листы всех действий в 8 направлениях, низ фигуры ×2, опорные виды: стопы (носки врозь, сквозь ногу или подол, рывки опорной стопы), руки и сумка сквозь тело, текстура, направление, обрезка; линейка всех персонажей по росту — масштаб друг к другу и к возрасту. Проверяются только персонажи, чьи файлы спрайтов изменились (`sprite_qa_state.json`); числовые углы стоп — у другого агента | `sprite_qa_<дата>.md` + листы с находками в `sprite_qa_<дата>/` |
| Комнаты (`ai_room_qa.yml`) | после каждой успешной сборки и публикации сайта (`build-and-publish`, через `workflow_run`), когда сайт уже отдаёт эту сборку; запрос `requests/room_qa.json` (`"rooms": "all"` или список) | глазами модели — комната в веб-сборке (хуки `?ambientprobe`): начальное состояние с Агатой вдали и вблизи (точки `walk_samples`), состояние после сцен комнаты, подписи по Пробелу. Слои и швы, порядок по глубине, Агата парит/тонет, масштаб против ориентиров `height_refs`, текст поверх арта, заглушки. Только комнаты, чьи данные или арт изменились (`room_qa_state.json`: `data/story/rooms/<R>.json`, `game/assets/rooms/<R>/`, `ambient`, `lights`) | `room_qa_<дата>.md` + кадры с находками в `room_qa_<дата>/` |
| Логика блока (`ai_story_logic.yml`) | пуш, добавляющий или меняющий `Docs/ACCEPTANCE_*.md` (разбираются изменённые разделы); запрос `requests/story_logic.json` (`"doc"` — весь документ) | блок глазами игрока против данных сюжета (сцены с условиями, комнаты с хотспотами и выходами, предметы, флаги, квесты, тексты), `SCENARIO_FINAL.md` и канона: шаги, которые игроку не вывести; обязательные предметы — пропустить, потерять, получить дважды; цель раньше объяснения; тупики; противоречия; расхождения данных и чеклиста | `story_logic_<веха>_<дата>.md` |
| Текст (`ai_text_lint.yml`) | пуш, меняющий `data/story/text/ru_*.json`, `scenes/*.json`, `flags.json`, `items.json`, `quests.json`, `locations.json`; запрос `requests/text_lint.json` | всё, что игрок читает и слышит: канон (возрасты, имена, «Дарья», Тихон, нет эха в конторе), опечатки, грамматика, пунктуация, единообразие имён и терминов, цель позже требования. По пушу — только новые и изменённые строки (весь текст — контекст); если видимый текст не менялся, API не вызывается | `text_lint_<дата>.md` |
| Подсказки против состояния (второй шаг `ai_text_lint.yml`, `tools/ai_checks/hint_state.mjs`) | тот же пуш, а также правка `data/story/rooms/*.json`; запрос `requests/hints.json` — все сцены | «Подсказка» показывает подсказки первой непройденной основной сцены с выполненными `requires` — где бы игрок ни был. Для каждой основной сцены: что уже сделано (флаги с текстом журнала и действием, которое их ставит), где действие сцены, цель журнала, подсказки. Классы дефектов: **подсказка про уже сделанное** (результат уже в `requires`: D5 — «ключ на дверь» при `house_unlocked`), **подсказка не ведёт к месту** (сцена становится текущей в другом месте, подсказки — только про действие на месте: M25 в день четвёртый), **подсказки нет**, **подсказка про другое**. Сцены, которые становятся текущими не там, где их действие, программа помечает сама (⚠) — модель решает, называет ли подсказка 1 место. Только сцены, у которых что-то из этого изменилось; модель `claude-opus-5-5` | `hints_<дата>.md` |
| Вся игра на непрерывность (`ai_continuity.yml`, `tools/ai_checks/continuity.mjs`) | **разово**, по пушу `requests/continuity.json` (поменять `run`) или вручную; по пушам текста сама не запускается | лучшая модель с длинным контекстом (`claude-fable-5-1`, запасная — `claude-opus-5-5`) читает ВЕСЬ текст игры в порядке сюжета: сцены E0–E5 с репликами и условиями, комнаты (реплики NPC и тексты по флагам, мысли Агаты, осмотры, выходы) в порядке, в каком сюжет в них приводит, предметы, истории Q01–Q10, журнал, подсказки, интерфейс — плюс `SCENARIO_FINAL.md` и канон. Три прохода с общим кэшированным началом: **непрерывность** (кто что знает когда, противоречие раньше сказанному, возраст/имена/счёт 20:1, цель после требования), **голоса и повторы** (тон каждого персонажа, повторяющиеся шутки и строки), **озвучка** (ударение, ё, омографы, числа, междометия; исправление — поле `voice_text`). Находки — с точными ключами и цитатами. Тот же корпус, что читает модель, собирается без API: `node tools/ai_checks/continuity.mjs --dump-only --dump <файл>`; оценка стоимости — `--dry` | `continuity_<дата>.md` + `continuity_<дата>.json` |

Важность находок: **критично** — противоречит канону или искажает смысл; **важно** — ошибка, заметная игроку или в озвучке; **мелочь** — пунктуация и шероховатости.
